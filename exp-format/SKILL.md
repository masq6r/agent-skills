# eXp 格式

帮助 agents 正确消费 eXp 格式的历史文件。格式名称采用 `eXp` 写法，识别用户提及的格式名称时不区分大小写；此规则不改变文件路径、字段名或合约代码的大小写要求。先阅读 [references/format.md](references/format.md)，取得准确路径、CSV 字段顺序、时间和数值语义；不要凭列名或通用期货数据惯例猜测格式。

## 使用方式

1. 确认用户提供的数据根目录、交易所、合约或品种、交易日范围及所需粒度。该技能不附带行情数据，也不假定源仓库或生产服务可访问。
2. 有源码时核对 `History/Readme.md` 与 `Writer.fs`、`HistoryRanking.fs`、`HistoryAdjustment.fs`、`HistoryRankStore.fs`；只有数据时检查真实表头、ZIP entry 和覆盖范围。参考文件记录的是已核对的格式基线，遇到不一致时报告版本差异，不静默改列或补值。
3. 从 `catalogue.csv` 或目标日 `listed/` 获取合约交割年和资料，用它定位文件。按交易所和合约标识联合关联，保留代码大小写及品种中的下划线。
4. 先验证表头和列数，再流式读取 CSV 或指定 ZIP entry。首行的 `#` 是表头标记，仅移除第一个字段开头的一个 `#`；不要跳过后把首条数据当表头。价格、成交额与换月因子需要精确计算时使用十进制数。
5. 验证实际输出：核对合约、交易日、行数、时间覆盖及缺失情况。区分缺少文件/entry、只有表头、数值为空和无效价格哨兵；不要把它们统一填成零。发布完整性按参考文件判断。

## 必须保留的语义

- `daily/minute/depth` 的目录年份是交割年；`listed/ranks` 是交易日年份，`rollovers` 是换月日年份。分钟和 depth 是每合约累积 ZIP，包内根目录按交易日保存 `yyyyMMdd.csv`。
- `TradingDay` 与自然日期不同。夜盘按交易日筛选，分钟 `Time` 保留自然日期，depth 由 `CalendarDay + Time` 组成自然时间；eXp 不使用 LEAN 的 4 小时时移，文件也不携带时区偏移。
- 分钟成交量/额是 bar 增量，depth 成交量/额是当日累计值，日线为全日值。depth 是行情快照，不是逐笔成交，也没有买卖盘报价和数量。
- 原始行情未做主力复权，不额外乘整数倍率。`Multiplier` 用于需要的合约金额计算，不用于还原 CSV 中的报价。
- `RankByOi` 与 `RankByVol` 分别定义排名。目标日收盘后的排名不能用于该日更早时刻选合约；回测应使用决策时点之前已知的排名。历史样本需要目标日的在市快照，不能用今天的合约目录代替历史在市集合。
- 换月列为单次事件值。分别检查 `AdditiveStatus` 和 `RatioStatus`，不可把不可用因子填成 `0` 或 `1`，也不能将单次因子误当累计复权值。

## 范围

默认围绕用户指定的文件完成读取、分析或消费代码开发。修改数据、补齐存量数据、修复发布状态或调用在线接口是另外的任务；本技能本身不授权这些操作。读取内部状态时不修改 manifest、覆盖报告或发布索引。
