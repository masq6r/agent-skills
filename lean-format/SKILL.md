# LEAN 期货数据格式

帮助 agents 正确消费和实现 LEAN 期货数据。格式名称 LEAN／Lean／lean 均可识别；存储名称和内容大小写仍遵循具体格式。技能不附带行情，也不依赖原始仓库路径或在线服务。

## 开始处理

1. 确定用户的数据根目录、目标 LEAN 版本、品种／合约、日期范围及分辨率。区分标准 LEAN 读取规则、本地 CHN 扩展和 History 存量数据的生成策略。
2. 先读 [references/format.md](references/format.md)，核对路径、entry 和字段。涉及夜盘、时区、日期归属、周末、节假日或数据转换时，再读 [references/china-time.md](references/china-time.md)。
3. 有源码时，以任务使用的 `LeanData`、行情读取器、`FutureDailyPlusBar`、`MapFile` 和 `MarketHoursDatabase` 为准；没有源码时检查真实 ZIP、CSV 及参考数据库，并说明未验证的引擎行为。技能中的提交只用于标记已核对基线，不代表用户当前版本。
4. 为消费代码明确数据身份、时间和数量语义，再读取／生成文件。按需使用十进制数，区分文件缺失、entry 缺失、空 entry 和无效数值；不要凭文件名猜所有字段或默认为零。
5. 验证任务实际产物：文件路径及 entry、列数、合约、覆盖区间、时间单调性与数量语义。做引擎兼容性结论时还要验证有效订阅时区、文件选日和市场时段过滤；文件可解压或 CSV 可解析不足以证明引擎会接收。

## 不能混淆的约定

- 本数据集的行情路径和 ZIP entry 为小写；CSV 中的合约标识、market、参考数据库键不因此全部改为小写。日线 entry 只有一个交割年月段和一个 `.csv`，不使用旧版的额外日期段或 `.csv.csv`。
- 日内 ZIP 按品种／交易日／类型组织，包内按交割合约区分；日线 ZIP 按品种／类型累积，每个交割月一个 entry。品种可含下划线。
- 国内期货的 `+4` 必须与交易日文件日期、平移后的市场时段及 `Pacific/Wake` 时区配套。固定偏移不能自动解决 CTP 交易日归属，也不能推广到任意 LEAN 数据源。
- 按该方案归档到周一文件的周五夜盘，在算法上海时间中变成周日晚间：行情顺序保留，真实 UTC 时间和周末时长改变。遇到新闻、多市场对齐、星期逻辑或持仓时长任务，先明确这一限制，不能仅减 4 小时恢复真实自然日期。
- LEAN tick 第三列是 `Quantity`，按单笔数量解释；History 存量 tick 写入的是累计成交量，直接聚合会重复累计。新增转换器应按目标数量语义处理，并核实交易日重置、缺失首条和异常累计值，不能默认为已正确转换的逐笔数据。
- `daily+` 是本地扩展，有专用读取器；其 `Time`／`EndTime` 为交易日上海时间 15:00 转到订阅交易所时区。不要套用标准 daily 或日内 `+4` 规则。
- 映射行日期是适用区间结束日，不是新合约生效日。历史文件的 mode 生成策略不能直接当作完整的 LEAN 标准换月策略，映射也不等于价格复权。
- Market hours database 参与时间解释、文件日期枚举、行情过滤和 fill-forward；CSV 已有记录不保证会交付算法。读取有效配置，不仅检查 JSON 是否存在。

## 范围与交付

围绕用户授权的数据与代码工作。检查格式不隐含原地修复、覆盖历史数据、恢复已删除生成器、连接账户或修改生产配置的授权。需要转换时默认准备独立输出，在实际修改源数据前遵循用户授权范围。

报告所用格式／源码基线、发现的实际差异、完成的验证及未验证部分。不要把解析、开市检查或合成样本验证称为完整策略回测或生产数据验收。
